# Brief, Plan, media, resume and progress

## Execute the requested scope

Read the selected Batch/profile, current stop target and existing project state.
Use the user's configured providers and native execution controls. A request
for preparation or a report does not start generation. When production is
authorized, continue the requested work without routine re-approval per title.
Do not introduce a separate pilot unless requested.

If no end stage was supplied, settle that material scope before paid execution.
For a preparation workflow modeled around images, propose stopping after content
images and thumbnails. Do not silently include audio, footage, export or upload.

Provider and UI details vary by installed version. Inspect the native controls
or applicable version documentation rather than guessing payloads. Preserve
authentication, source binding, ownership, cleanup and retry behavior.

## Brief and Plan

Use the installed brief builder and inspect the actual resulting brief. Confirm
title, locale, duration, promised counts, format, room/property scale, references,
narration direction, thumbnail style and title template.

Keep hooks, causality and progression specific to the title. Deliver the
promised ideas, examples or reveal. Avoid unsupported measurements, invented
owners or budgets, factual claims borrowed from a different property, and
repetitive visual padding.

Generate plans with the selected provider through HDS. Validate the canonical
plan using the installed native checks. Review narrative progression, originality,
shot/prompt fit and reference continuity on actual production results. Different
plan requests alone do not prove different content.

Reuse a valid plan instead of ordering a replacement merely because a session
or agent changed. Respect existing review mode and the user's accept/retry choice.

## Images and optional later stages

Resolve assigned references from the active collection. The supported number of
images per request can differ by provider; a larger moodboard library does not
mean every reference is sent on every generation.

Honor the selected Combined recipe, storage quality and thumbnail provider.
Keep the content split separate from the thumbnail recipe. Preserve native
allocation, rounding and provenance; do not regenerate valid assets to make
provider attribution look exact.

Follow the native sequence: complete the selected work for the current title
before moving on when HDS requires that order. Use its available worker settings;
do not assume a fixed worker count per browser profile.

Check required image IDs, valid saved content and thumbnail candidates through
native readiness. A file's existence does not prove decodability, ownership or
completeness. Review artistic fit on production examples without building a new
quality-audit system or restarting every prior provider investigation.

When later stages are requested, follow the installed narration/audio, footage
and export flow. Upload or publication requires the user's corresponding scope;
creating a finished file is distinct from publishing it.

## Resume and handoff

Use native Start/Continue/Stop, disk-first results and bounded retry behavior.
Do not create a second writer for the same project, reset a Batch to recover it,
silently switch providers, or skip missing work as if it were complete.

Record actual completed units, remaining units, current owner/path and evidence
in the same ledger. Preserve chosen names, handles, URLs and transfer notes when
refreshing a workbook, matching records by their identities.

Use existing progress weights when supplied. Otherwise agree on meaningful
outputs rather than counting tests or files. Partial images count only against
the verified requirement list. Do not claim native validation from the bundled
diagnostic helper, or cross-device completion without opening on the destination.
